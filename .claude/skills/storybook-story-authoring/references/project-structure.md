# 파일 위치와 구조 규칙

**프로젝트에 기존 컨벤션이나 아키텍처 문서(CLAUDE.md, README, lint 설정 등)가 있으면 그것을 따른다.** 아래는 어떤 구조에도 적용되는 원칙과, 컨벤션이 없을 때의 기본값이다.

## 1. 위치: 컴포넌트 옆에 둔다

```
<컴포넌트가 있는 폴더>/
├── Button.tsx
├── Button.stories.tsx
└── index.ts            # Button만 export (스토리는 export하지 않음)
```

- 루트의 별도 `stories/` 폴더에 모으지 않는다. 컴포넌트를 옮기거나 지울 때 스토리가 함께 따라가고, 고아 스토리가 남지 않는다.
- 프로젝트가 폴더를 역할별로 나눈다면(예: 모듈 안에 `ui/`, `model/`, `api/` 등), 스토리는 **UI 컴포넌트가 있는 폴더**에 둔다.
- 스토리 파일은 `.storybook/main.*`의 `stories` glob에 포함되어야 한다. 새 위치에 만들었다면 glob에 잡히는지 확인한다.

## 2. title: 폴더 구조를 반영한다

1. 기존 스토리가 명시적 `title`을 쓰면 같은 규칙으로 작성한다.
2. 기존 스토리가 `title`을 생략(경로 기반 자동 title)하면 생략한다.
3. 기존 스토리가 없으면: 소스 루트 이후의 폴더 계층을 따라 title을 만든다. 사이드바 구조가 폴더 구조와 일치해야 찾기 쉽다.
   - 의미 없는 중간 폴더(`components/`, `ui/`, `src/` 등 역할만 나타내는 폴더)는 빼도 된다. 단, 프로젝트 전체에서 일관되게 적용한다.
   - 예: `src/components/Button/Button.tsx` → `Components/Button`
   - 예: `src/features/checkout/ui/CartSummary.tsx` → `features/checkout/CartSummary`

## 3. import 경계를 지킨다

프로젝트가 모듈·레이어 간 의존 방향이나 public API 경유를 강제한다면(아키텍처 문서, ESLint import/boundaries 규칙, 아키텍처 전용 린터 등), 스토리도 같은 규칙을 지킨다.

- 같은 모듈 안의 컴포넌트는 상대 경로로 직접 import해도 된다.
- 다른 모듈의 것은 그 모듈의 public API(또는 mock 전용 진입점)를 통해서만 가져온다. 다른 모듈의 내부 파일을 직접 import하지 않는다.
- 하위 모듈의 스토리가 상위 모듈을 import하는 등, 프로덕션 코드에서 금지된 방향의 의존을 스토리에서도 만들지 않는다.
- 린터가 스토리 파일이나 mock 진입점을 경고하면, 규칙을 어기도록 스토리를 바꾸지 말고 린터 설정에서 스토리 파일 예외 처리가 필요하다고 보고한다.

## 4. 스토리용 헬퍼와 mock 위치

- 프로젝트에 이미 mock·fixture·decorator를 모아두는 위치가 있으면 그것을 쓴다 (예: `src/mocks`, `test/fixtures`, 공용 `lib/storybook` 등).
- 없다면:
  - **특정 도메인 데이터의 픽스처·핸들러**는 그 데이터를 소유한 모듈 안에 둔다. 여러 스토리가 재사용할 수 있게 한다.
  - **여러 스토리가 공유하는 decorator·헬퍼**는 공용 유틸 위치에 둔다.
  - **전역 Provider 래핑**은 `.storybook/preview.*`에 둔다.
- 스토리용 헬퍼·mock을 프로덕션 진입점(`index.ts` 등)에서 export하지 않는다. 다른 모듈과 공유해야 하면 `mocks.ts` 같은 **별도 진입점**으로 분리해 프로덕션 번들에 섞이지 않게 한다.

## 5. 어디까지 스토리를 쓰는가

컴포넌트가 앱 구조의 어느 수준에 있는지에 따라 범위를 조절한다.

| 수준 | 예시 | 범위 |
|---|---|---|
| 공용 UI (디자인 시스템) | Button, Input, Modal | 가장 촘촘하게. 모든 variant·상태·접근성 |
| 도메인 표시 컴포넌트 | UserCard, ProductItem | 데이터 형태별 표시 (긴 이름, 빈 값, 상태값별) |
| 기능 단위 컴포넌트 | LoginForm, AddToCart | 인터랙션 테스트의 중심. 성공/실패 흐름 |
| 조합 블록 | Header, Sidebar | 조합 결과와 로딩/에러 등 대표 상태 |
| 페이지 | ProfilePage | 최소한. 필요할 때만 |
| 앱 진입점·라우팅 | App, 라우터 설정 | 작성하지 않음 |

여러 화면을 오가는 흐름은 스토리가 아니라 E2E 테스트 영역이다.
