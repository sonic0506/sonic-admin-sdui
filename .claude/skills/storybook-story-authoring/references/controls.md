# Props 컨트롤 판단·처리 기준

Storybook은 컴포넌트의 타입을 분석(docgen)해 Controls 패널을 만든다. 분석기가 타입을 풀지 못하면 열거형 props가 object 컨트롤("Set object")로 나오고, 누르는 순간 `{}` 같은 잘못된 값이 들어가 스타일·동작이 깨진다. **인터랙션 테스트는 이 문제를 잡지 못하므로** 따로 확인한다.

문법(`argTypes`의 정확한 형태, 설정 키 이름)은 MCP 지침과 설치된 버전을 따른다. 여기서는 판단 기준만 정한다.

## 1. 깨지기 쉬운 타입

기본 분석기(Vite 계열 프레임워크는 `react-docgen`)는 컴포넌트 파일 안의 **리터럴 유니언**(`'sm' | 'md'`)은 잘 읽지만, 아래 경우에는 자주 실패한다.

- `cva`의 `VariantProps<typeof xxxVariants>` (shadcn/ui 계열 전부 해당)
- 매핑·조건부·유틸리티 타입으로 만든 props (`keyof typeof MAP`, `Pick`/`Omit` 조합 등)
- 다른 모듈·패키지에서 가져온 유니언 타입

## 2. 확인 방법 (위에서부터 가능한 것)

1. MCP의 컴포넌트 문서 도구(`get-documentation` 등)로 props 타입을 본다. 열거형이어야 할 prop이 object·unknown·any로 나오면 깨진 것이다.
2. 실행 중인 Storybook의 Controls 패널(`preview-stories` 또는 브라우저)에서 해당 prop이 select/radio인지 본다.
3. 둘 다 불가능하면 1번의 "깨지기 쉬운 타입"에 해당하는지로 판단하고, 해당하면 깨진 것으로 간주해 처리한 뒤 보고에 "실제 화면 미확인"이라고 적는다.

## 3. 처리 순서

**A. 원인이 프로젝트 공통인지 먼저 본다.**
같은 패턴(예: `cva`/`VariantProps`)을 쓰는 컴포넌트가 프로젝트에 여러 개 있고, `.storybook/main.*`가 기본 분석기를 쓰고 있다면 원인은 설정이다.

- 분석기를 `react-docgen-typescript`로 바꾸는 설정 변경을 **제안**한다. 설정 파일 변경이므로 승인 없이 적용하지 않는다(하드 규칙 19).
- 제안할 때 알릴 것: 영향받는 컴포넌트 수(검색 결과 기준), 장점(모든 스토리의 컨트롤이 한 번에 맞아짐), 단점(TypeScript 분석을 해서 Storybook 시작·HMR이 느려질 수 있음).

**B. 승인 전이거나 거절되었거나 원인이 그 컴포넌트에만 있으면, 스토리에서 보완한다.**
meta의 `argTypes`에 해당 prop의 컨트롤 종류와 허용 값을 명시한다. 이번 작업의 스토리가 승인 여부와 관계없이 바로 올바르게 동작하게 한다.

**C. 설정 변경이 승인되어 적용했다면:**
- Storybook을 다시 띄워 2번 방법으로 다시 확인한다.
- 해결되었으면 **이번 작업에서 보완용으로 넣은** `argTypes`를 제거한다. 다른 사람이 작성한 기존 스토리의 `argTypes`는 손대지 않고 정리 가능하다고 보고만 한다.
- 설정을 바꿔도 남는 prop만 B 방식으로 보완한다.

## 4. `argTypes` 작성 기준

- 허용 값은 **소스에서 정확히 옮긴다** (`cva`라면 `variants` 객체의 키, 유니언이라면 그 리터럴). 추측하거나 일부만 넣지 않는다. 기본값도 포함한다.
- 값을 소스에서 옮겼다는 짧은 주석을 남긴다. 컴포넌트에 값이 추가되면 함께 고쳐야 한다는 신호다.
- 문제가 된 prop만 지정한다. 정상적으로 생성된 컨트롤까지 덮어쓰지 않는다.
- 컨트롤 문제를 해결하려고 컴포넌트의 타입 선언을 고치지 않는다(하드 규칙 18). 리터럴 유니언으로 바꾸는 편이 낫다고 판단되면 보고에 제안만 한다.
